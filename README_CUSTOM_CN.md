# 按人用量占比定制版

版本：`2.0.11-luoshui.3`。基于上游 `3999ae7`，供现有 CPA 使用；不是上游官方版本。

## 使用方法

1. 打开 Token 用量统计，进入完整模式并完成管理密钥鉴权。
2. 页面增加“按人用量占比”，展示名称／说明、请求次数、总 Token、总费用、失败次数及占比。
3. 切换“请求次数”、“总 Token”或“总费用”，圆环及表格会按对应指标重新排序。
4. 点击姓名旁的铅笔设置名称。名称保存在插件数据库中，刷新和重启后保留。
5. 时间、来源和顶部 API Key 筛选适用于此排行。模型图中的选中／隐藏操作不影响此排行。

CPA 配置面板的“名称／说明”保存在浏览器本地。本版仅读取当前服务器的 `api-key-names:v1:` 名称记录，按 CPA 原有 SHA-256 身份契约匹配客户端密钥，并通过完整模式接口导入没有插件标签的密钥。导入后保存在插件数据库中；其他设备也可复用。已有的插件标签继续使用，不被自动覆盖。若当前浏览器没有备注，显示“未设置备注”，可点击铅笔填写。不会把脱敏密钥当成人员名称。相同姓名的两个密钥分别计数。更换加密密钥导致的不同代际保持分开，避免错误合并。

占比的分母是当前时间、来源和 API Key 筛选范围内的总量；选择某一个 Key 后其占比通常为 100%。请求次数沿用宿主用量记录口径，重试或故障切换可能产生多条记录，不等于对话次数，也不是对入口 HTTP 请求的去重计数。历史数据没有保存密钥时归入“未记录密钥”，无法事后还原使用者。

悬浮或聚焦饼图扇区可查看对应姓名、脱敏密钥、请求数、Token、总费用、失败数及占比。总费用沿用当前模型价格、缓存和服务层级计费逻辑，为估算值；未定价的请求不计为零，部分定价显示 `*`。

## 对代理业务的影响

此次修改仅增加查询时的按 Key 汇总和完整模式页面，不改变模型请求、认证、路由、重试、限流、用量采集和数据库格式。普通模式不返回密钥清单或按人图表。

原插件通过 CPA 后台用量队列工作，通常不会同步阻塞模型响应，但仍消耗同一进程的 CPU、内存和磁盘。慢磁盘、大范围查询或插件故障仍可能间接影响服务；本次测试不构成压力测试。替换插件如需要重启 CPA，会短暂停服并可能中断正在进行的请求。

## 发布与恢复

Linux amd64 动态库使用 Go 1.26、c-shared 构建。发布前保留旧插件，停止 CPA 后冷备配置、插件、认证和完整数据目录，再替换原插件库并启动。必须确认新版本加载、统计接口和代理接口正常；失败时恢复旧插件并启动原 CPA。不要将旧版与新版动态库同时放在扫描目录中。

本次没有迁移数据库。恢复插件时默认继续使用当前数据，不用旧备份覆盖新增请求记录。只有确有数据库损坏时才另行评估恢复数据。

CPA 中继续把此插件标记为本地维护（`local-custom`），以免官方商店覆盖定制版。保持插件 ID 和数据目录不变；若部署时改了动态库文件名，要同步 CPA 配置中的本地插件文件版本。

## 同步官方更新

Fork 的 `main` 跟随官方仓库，`codex/api-key-usage-share` 保存定制代码。以下命令假定 `origin` 是自己的 Fork，`upstream` 是 `AITNR/cap-token-usage-tracker`，并且工作区没有未提交改动。从已核对的官方正式版标签合并，避免把未发布的改动带到服务端：

```sh
git fetch upstream --tags
git switch main
git merge --ff-only upstream/main
git push origin main
git switch codex/api-key-usage-share
git merge vX.Y.Z  # 替换成已核对的官方正式版标签
npm ci --ignore-scripts --no-audit --no-fund
go test ./... -count=1
git push origin codex/api-key-usage-share
```

在 Linux amd64 和 Go 1.26 环境下执行 `VERSION=X.Y.Z-luoshui.1 bash scripts/build.sh`，把 `dist/` 里的产物按上面的发布流程部署。先核对插件加载版本，再检查完整模式的姓名、费用和历史日期筛选。定制分支的测试和打包在本地执行。

Fork 只保存源码、文档和模拟测试数据。不要提交 API Key、管理密钥、实际 CPA 配置、认证目录、日志、统计数据库、截图或任何部署备份。构建和测试不需要线上凭据。
